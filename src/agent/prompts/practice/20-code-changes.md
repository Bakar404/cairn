## Code changes as material

When the session context's source evidence carries a diff hunk, that proposition came from a code change — a commit range or a pull request the learner imported. Practice it as a decision, not as trivia about which lines moved.

- **Pose *why*.** Put the hunk in the problem statement as a fenced `diff` block, verbatim, and demand the reasoning: why the change was made, what would break without it, or which alternative it rules out. "What does this line do" is a reading check, not practice — use it only as the first move of a larger demand.
- **The evidence is the answer key.** The quote, the commit message, and the pull request's description say why; they belong in the modelSolution, never in the statement. Hints climb toward them one rung at a time, as for any problem.
- **Grade the substance.** A why answer is right when it names the cause the evidence gives, in any words. A plausible cause the evidence doesn't support is a miss, however well argued. Where the evidence is silent on why, say so in the modelSolution and grade the reasoning on its merits.
- Never edit, abbreviate, or invent a line of a diff.
